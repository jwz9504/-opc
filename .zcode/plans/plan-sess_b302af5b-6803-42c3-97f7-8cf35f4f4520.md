## 总体实施方案

当前工作区为空，按两份手册从零建设，不假设已有业务代码。采用 Python 3.11+、Pydantic v2、pytest、Ruff、mypy/pyright 和 LangGraph；阶段 0～7 默认使用 Stub/Fake 模型，真实模型和外部工具延后到阶段 8。

### 第一批实现：阶段 0～2（先建立可信内核）

1. **阶段 0：工程基线**
   - 创建 `pyproject.toml`、锁定依赖、`README.md`、`.env.example`、基础配置模块和 `src/agent_meeting` 包。
   - 创建推荐目录：`schemas/`、`policies/`、`nodes/`、`services/`、`api/`、`tests/`、`docs/adr/`、`docs/acceptance/`。
   - 建立 dev/test/prod 配置分层，测试默认禁止真实模型、网络和生产服务。
   - 建立 Ruff、类型检查、pytest markers、覆盖率配置及 CI 配置。
   - 写入 ADR-0001，冻结阶段化工作流、治理版本、人工最终批准、Checkpoint/Ledger/Outbox/Branch Task 四层恢复边界。
   - 添加阶段 0 验收记录模板和 Windows/Linux 可执行命令。

2. **阶段 1：Schema、State 与 Reducer**
   - 用 Pydantic v2 实现治理版本：`ScopeVersion`、`AgendaVersion`、`EvaluationPolicyVersion`，含 confirmed/frozen 不可变语义。
   - 实现 `ArtifactEnvelope` 和规范化内容哈希，强制所有下游产物绑定三类治理版本。
   - 实现核心 Artifact：Evidence、SourceSnapshot、Claim、Proposal、ProposalComparison、ProposalDisposition、DecisionRecord、Critique、CritiqueResolutionEvent、ReworkPlan、ReportRevision、ReportStatement、GateResult、SoftEvaluation、PairwiseComparison、GroundingFinding、RegressionFinding、HumanDecision、ActionItem、MinorityOpinion、AuditEvent。
   - 定义精简 `MeetingState`，只存 ID、索引、active 指针和必要摘要；大型原文只保存 Artifact Store 引用。
   - 实现 append-only、merge-by-ID、versioned-upsert、active-pointer 和治理绑定校验；禁止直接覆盖历史产物。
   - 实现 Critique Resolution Event 的纯函数投影，确保 `resolved` 只能由合法的独立验证事件产生，支持 reopened。
   - 为重复事件、乱序事件、并行合并、active pointer 更新、序列化和哈希稳定性建立单元/契约测试，覆盖 Reducer 结合性、交换性和幂等性。

3. **阶段 2：纯规则治理引擎**
   - 实现权限矩阵与事件授权：作者只能 `addressed`，验证者不能是修改者，`accepted_risk` 仅人工可创建。
   - 实现 Proposal 标准化后的硬约束筛选、淘汰原因、支配关系和 shortlist 上限。
   - 实现 Critique 分类、终态和关闭依赖规则。
   - 实现治理版本变更的依赖失效传播：受影响项 stale，不确定项 stale_pending_review，不受影响项保持 active。
   - 实现确定性 Preflight/Hard Regression：引用、必填章节、决策/少数派/行动项、责任人、验收标准、未授权区域变化、预算、Critical Critique 重现等检查。
   - 实现硬门禁聚合、软评估聚合、`unknown/abstain/tie/depends` 路由、轮次/预算上限和 Final Freeze 前置条件；确保硬失败不可被软分覆盖，未人工批准不能冻结。
   - 采用表驱动和负向测试，至少覆盖手册要求的 10 个 Hard Regression 场景、权限矩阵、unknown/abstain、人工风险接受和最终审批缺失。

### 第二批实现：阶段 3～6（接入可恢复图和质量闭环）

4. **阶段 3：LangGraph 骨架**
   - 定义节点契约、Stub 节点、条件路由、phase/round/budget 限制和拓扑测试。
   - 接入开发 Checkpointer 与稳定 `thread_id`；实现治理确认、修改、终止、最终审批等 `interrupt/resume` 路径。
   - 集成测试覆盖正常路径、进程重启恢复、取消、超限转人工和恢复幂等。

5. **阶段 4：Proposal 闭环**
   - 实现 research/ideate fan-out/fan-in、标准化去重、硬筛选、shortlist、成对比较、Pareto/tie/depends 人工选择和 DecisionRecord。
   - 保留 provenance、淘汰原因、未选方向和组合 Proposal 的重新筛选证明。

6. **阶段 5：Revision/Critique/Regression**
   - 实现 Baseline/Candidate、红队 Critique、Triage、ReworkPlan、定点返工、独立验证和回归比较。
   - 同时执行确定性回归和匿名 A/B 语义比较，保存分歧、置信度、tie/depends；覆盖 promote/reject/revise/human_tradeoff 和最大返工轮次。

7. **阶段 6：Grounding/Gates/Final Decision**
   - 先生成结构化 ReportStatement，再确定性渲染 Markdown/JSON。
   - 实现 Sentence→Claim→Evidence→SourceSnapshot 结构校验和语义 Grounding 结果；禁止 Validator 升级 Claim。
   - 实现 factual/feasibility/risk/compliance/actionability 硬门禁、软指标和最终聚合，确保报告包含固定章节、少数派、行动项、责任人和证据附录。

### 第三批实现：阶段 7～9（可靠执行、真实服务和发布）

8. **阶段 7：恢复与副作用安全**
   - 实现 Operation Ledger、Outbox、BranchTask、幂等键和 Dispatcher；副作用前记录 Operation，外部写入必须审批后执行。
   - 加入崩溃注入、并行部分失败补跑、Outbox 提交后崩溃、原子文件写入和死信测试，证明重复发布/写入为 0。

9. **阶段 8：真实模型、检索和安全**
   - 建立 Model Registry、Artifact/Evidence Store、Prompt Version、有限重试/schema repair/fallback、最小工具权限、脱敏和提示注入隔离。
   - 用 Golden Cases 评估结构成功率、Grounding、成本、延迟和失败路由；Live Model 测试默认手动/预算内执行。

10. **阶段 9：API/E2E/Release Candidate**
    - 实现会议创建、运行、查询、恢复、取消、报告和审计 API，加入鉴权、会议级授权、请求幂等和 resume token。
    - 实现最终 Markdown/JSON 导出、完整审计、运行手册、备份恢复、告警、E2E/安全/UAT 和发布清单。

### 执行与验收约束

- 每批完成后运行对应单元、契约、集成测试和覆盖率检查，生成 `docs/acceptance/phase-N.md`，记录命令、退出码、覆盖率和证据。
- 先完成并验收阶段 0～2，再进入 LangGraph；任何 Reducer 非幂等、权限可绕过、硬门禁可被软分覆盖或历史可覆盖时停止推进。
- 所有新增 Artifact、节点和外部操作都必须绑定治理版本、产生 AuditEvent，并有失败路径测试。
- 首轮实现以可运行 MVP 内核为目标，不连接真实模型、不执行真实外部写操作；阶段 6 后可形成 Stub MVP，阶段 7～9 完成生产候选版本。
